# GlobalShopCo — Vertical Batch Protocol

Status: OWNER-DIRECTED OPERATING PROTOCOL
Effective: 2026-09-14

## Trigger

When the owner says any equivalent of:
- `cont`
- `continue`
- `continue autonomously`
- `continue autonomously vertically`

the GlobalShopCo Overseer should execute a fresh vertical batch using this protocol.

## Required order

### 1. Fresh repository scan
Before selecting tasks, inspect current relevant state in:
- `darrinbaldwindev/GlobalShopCo`
- `darrinbaldwindev/GlobalShopCo-Headless`
- current active catalogue/headless branch(es)
- active control/launch/channel issues that materially affect the batch
- latest meaningful commits since the previous batch

Do not reuse stale assumptions where the repo has moved.

### 2. Create or refresh the batch file
Create a dated/numbered file under `docs/batches/` recording:
- exact starting branch/head where relevant;
- fresh scan findings;
- active vertical objective;
- task stack ordered by commercial value;
- dependencies/blockers;
- hard boundaries;
- anti-idle fallback tasks;
- success criteria.

### 3. Execute the batch in the same run
Do not stop after planning.

Work down the task stack autonomously until useful independent work is exhausted or a hard authority/data blocker remains.

A good batch should combine complementary work where possible, for example:
- supplier discovery + exact SKU screen + competitor screen;
- Pet matrix + supplier-data unlock specification;
- Baby matrix + Safety cross-vertical reuse;
- Home candidate validation + replacement-candidate research;
- headless category contract reconciliation + catalogue-readiness check.

### 4. Evidence over catalogue count
Do not pad Shopify or research matrices with weak candidates.

Reject or HOLD candidates when:
- acquisition cost is unknown;
- freight/free-delivery economics are unknown;
- supplier permission is unclear;
- product identity is ambiguous;
- exact market pricing destroys margin;
- returns/compliance risk is disproportionate;
- product is a poor fit for the intended headless niche.

### 5. Anti-idle behaviour
If the current vertical is blocked by account-gated data, immediately continue useful independent work such as:
- exact market comparisons;
- another supplier lane;
- next niche candidate matrix;
- cross-vertical reuse mapping;
- Home Organisation validation;
- Mobile/Computer passive-accessory diversification;
- headless data-contract/readiness reconciliation.

Do not abandon the batch because one supplier or SKU is blocked.

### 6. Shopify mutation rule
Controlled Shopify DRAFT creation is allowed only when current owner direction and evidence support a serious qualification record.

Do not:
- make products ACTIVE without explicit publication authority;
- create speculative retail-looking drafts to simulate catalogue progress;
- invent supplier costs, freight, stock, compliance, relationships or margins;
- expose A$0/research placeholders as purchasable headless products.

### 7. Preserve governance boundaries
Never use a vertical batch to:
- mutate the pinned AgentOS Level-2 fixture outside its canonical flow;
- merge/approve/mark-ready/rebase/deploy without authority;
- change credentials;
- contact suppliers or make purchases without authority;
- install marketplace apps or connect seller accounts without authority;
- create alternate catalogue, scheduler, authority, ledger, governance or source-of-truth systems.

Shopify remains canonical commerce/product authority. WordPress/headless remains presentation/merchandising.

### 8. Persist results
After meaningful execution:
- create/update the relevant research artifact(s);
- update the batch file with executed result and successor queue;
- add a durable issue comment when it materially improves coordination;
- record exact blockers rather than vague “needs more research” statements.

### 9. Successor queue
Every batch should finish with the next highest-value executable tasks already identified, so the next owner `cont` begins with a rescan and then immediately resumes useful work.

## Default vertical priority while current headless plan remains unchanged

1. Pet — commercial economics unlock and assortment depth
2. Baby — commercial economics unlock and assortment depth
3. Safety — reuse qualified Baby/Pet identities + specialist additions
4. Mobile & Computer Accessories — supplier diversification, passive accessories first
5. Home Organisation — validate/replace existing candidates in parallel

Fresh repository evidence can change this ordering.

## Definition of useful batch completion

Batch completion means one or more of:
- a meaningful evidence gap closed;
- a durable candidate/rejection matrix produced;
- a supplier lane materially qualified or rejected;
- a precise account/owner blocker defined;
- a justified Shopify DRAFT qualification record created;
- a vertical moved materially closer to 5–10 evidence-complete products;
- a headless/category contract reconciled against current catalogue state.

It does **not** imply site-wide GREEN, launch approval, deployment or product publication.
